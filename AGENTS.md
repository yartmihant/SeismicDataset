# SeismicDataset — исследовательские дневники

Проект исследует подготовку EFVB/ECVB и влияние сглаживания границ материалов на сейсмические волны. Общение, дневники и отчёты ведутся по-русски. Структура и правила перенесены из соседнего MilenSem2D; предметные названия и главы адаптированы к этому исследованию.

## Структура

- `dev_<P>_<CH>_*.py` — первичные исследовательские дневники в императивном Jupyter-style.
- `dev_<P>_<CH>_*.ipynb` — представления дневников с результатами; редактировать исходный `.py`, затем конвертировать.
- `dev_<P>_<CH>_*_summary.md` — краткие рефераты глав с задачей, результатом, ограничениями и полным перечнем входов/выходов.
- `src/` — исходные данные, только для чтения; тяжёлые исходники не входят в Git.
- `data/dev_<P>_<CH>_*/` — расчётные данные и компактные JSON-свидетельства.
- `img/dev_<P>_<CH>_*/` — иллюстрации главы; массовые изображения не входят в Git.
- `scripts/dev_<P>_<CH>_*/` — вычислительные утилиты соответствующего этапа; общий код путей находится в `scripts/project_paths.py`.
- `docs/` — подробные протоколы, отчёты, описание среды и карта переноса.
- `presentation/` — презентации исследования.
- `.venv/` — собственная локальная среда; `pyproject.toml` и `uv.lock` задают зависимости.

## Главы

1.1 — `dev_1_1_dataset_preprocessing.py`: предобработка, устройство датасета, глобальные шкалы и статистика материалов.

1.2 — `dev_1_2_smoothing_pilot.py`: геометрия сглаживания, пилот ECVB 12404, контроль сходимости, повтор CU и отдельный опыт ECVB 00065.

1.3 — `dev_1_3_point_source.py`: точечный источник 30 Гц, верх 140×5 м, слой 175 м, контроль p4/p5 и дополнительная проверка p3, регистрация U/V/энергии. По текущему поручению выполняется только центральный источник x=350 м на обеих моделях; остальные положения отложены. Серия p3 хранится отдельно от прежних результатов p4/p5. Дневник читает сохранённые результаты и не запускает решатель.

1.4 — `dev_1_4_server_preparation.py`: подготовка кафедрального сервера saturn к расчёту датасета, read-only аудит оборудования/загрузки/диска и оценка хранения сейсмограмм 60000×5 опытов. Для полной серии приняты p4, только Vx/Vy, 70 приёмников x=5,15,…,695 м, 2001 отсчёт, float64; расчёт чанками, размер после очистки и нового замера места. SSH доступен с текущей рабочей станции; общий сервер, системные настройки и чужие задания не изменять. Дневник читает локальные свидетельства без SSH и запуска решателя. Полная серия и новый режим записи пока не реализованы/не запускались.

## Правила дневника

1. Соблюдать [PY_FORMAT_RULES.md](PY_FORMAT_RULES.md), скопированный из MilenSem2D. Его правила оформления относятся к дневникам `dev_*.py`; CLI-утилиты в `scripts/` могут иметь `main()`.
2. Дневник начинается названием исследования, главой и описанием задачи; последовательность каждого раздела — объяснение, вычисление, вывод. Верхнеуровневые тройные строки становятся Markdown-ячейками. Обёртка `main()` в дневнике запрещена.
3. Все данные сохранять в `data/`, рисунки — в `img/`, с префиксом этапа в имени или каталоге. Временные файлы размещать в корне с явным временным именем и убирать после работы. Кэши среды допускаются в скрытых каталогах корня.
4. Завершать каждую главу содержательными выводами и поддерживать её summary, указывая входные и выходные файлы.
5. Не изменять исходные поля в `src/`. Не исправлять исторические результаты и их SHA256 задним числом. Новая серия получает новый каталог.
6. Агенту разрешено использовать `py2jupyter` для конвертации исследовательских скриптов в `.ipynb` и обратно в пределах текущей задачи. Первичный источник — `.py`; `.ipynb` являются производными и не редактируются вручную. Проверять цикл `.py → .ipynb → .py`. Разрешение конвертации не разрешает автоматически выполнять тяжёлые расчётные ячейки.
7. Отчётный запуск читает сохранённые метрики и рисунки. Полная обработка 60000 моделей, генерация массовых картинок и GPU/CEED-расчёты запускаются только по отдельному прямому поручению.
8. После изменения Python сначала запускать mypy через собственную `.venv`, затем адресные проверки. Типизировать Python, использовать `typing` и `dataclass`; не вводить `Any` для обхода ошибок.
9. Связь с SEMGPU — установленный пакет `semgpu2`. Не добавлять TrySEMGPU или его `research/` в `sys.path`. CUDA/CEED-профиль и фактическая native-библиотека фиксируются отдельно от Python-зависимостей.
10. Каждый Markdown-абзац занимает одну физическую строку. В Markdown-ячейках дневников и `.ipynb` формулы оформлять выносными блоками `$$...$$`, с разделителями на отдельных строках; не использовать `\(...\)` и `\[...\]` в этих ячейках.

## Changelog и Git

Записывать собственные постоянные изменения в `CHANGELOG.md`. Дополнять существующий `[Unreleased]`; если его нет, создавать блок следующей patch-версии, не меняя `VERSION`. Разделы: Добавлено, Изменено, Исправлено, Убрано.

Git по умолчанию используется только для чтения. Изменение индекса, истории, веток и remote требует прямого поручения пользователя; ранее данное разрешение действует в своём scope. Текущее поручение разрешает локальную настройку нового проекта и исключение тяжёлых объектов. Push не разрешён. Резервная копия прежнего Git сохраняется локально до отдельного решения пользователя.

Исследовательские наблюдения не являются независимой валидацией решателя. Отделять результаты завершённых запусков, исторические свидетельства, отсутствующие локальные массивы и ещё не выполненные проверки.

# SeismicDataset

Исследовательский проект подготовки датасетов EFVB/ECVB. Исходные данные содержат 60000 моделей 700×700 м, по два поля VP/VS на ячейках 70×70. Численная технология подключается как внешний пакет `semgpu2` из соседнего TrySEMGPU; проект имеет собственную среду и Git-историю.

Глава 1.4 — [Подготовка кафедрального сервера](dev_1_4_server_preparation.py), [Notebook](dev_1_4_server_preparation.ipynb), [Summary](dev_1_4_server_preparation_summary.md). Принята запись только Vx/Vy на 70 приёмниках x=5,15,…,695 м: 60000 моделей × 5 источников требуют 672,336 ГБ сигналов float64. Расчёт планируется чанками; их размер определяется после очистки диска. Среда и массовый режим записи ещё не подготовлены, серия не запускалась.

Дневники используют сохранённые метрики и иллюстрации. Их выполнение не запускает массовую обработку, сеткопостроение, SSH или GPU/CEED-расчёт. Первичный редактируемый источник — `.py` в стиле MilenSem2D; `.ipynb` содержит производное представление и выводы ячеек.

## Среда и запуск

См. [подготовку среды](docs/ENVIRONMENT.md). На Linux отчётные дневники запускаются из корня:

```bash
.venv/bin/python dev_1_1_dataset_preprocessing.py
.venv/bin/python dev_1_2_smoothing_pilot.py
.venv/bin/python dev_1_3_point_source.py
.venv/bin/python dev_1_4_server_preparation.py
```

В Jupyter выбрать интерпретатор `.venv/bin/python`; на Windows — `.venv\Scripts\python.exe`. Для headless-запуска можно задать `MPLBACKEND=Agg`. Команды полной обработки и отдельных расчётов находятся в summary глав и [каталоге скриптов](scripts/README.md).

## Что хранится в Git

Сценарии, первичные дневники и их отчётные ноутбуки, правила, рефераты, протоколы, компактные JSON, отобранные иллюстрации и итоговая презентация. Исходные 120000 текстовых файлов, ZIP, массивы NPZ/NPY, сетки, native-библиотеки, массовые preview и `.venv` хранятся локально и исключены через `.gitignore`.

Клон репозитория позволяет читать отчёты и выполнять дневники по компактным результатам. Для повторного расчёта необходимо восстановить исходные/расчётные данные согласно [описанию src](src/README.md) и [описанию data](data/README.md). Git не является резервной копией этих массивов; адрес внешнего хранилища пока не задан.

## Результат и границы

Установлены глобальные диапазоны скоростей и распределения числа материалов. В главе 1.2 пилот №12404 показывает чувствительность поздней коды к сглаживанию при хорошем запасе относительно наблюдаемой пространственной поправки. Для полной записи пятикратный запас не достигнут; №65 не имеет отдельной серии сходимости. Выполненный силовой источник в центре отличается от исходного задания с предписанным перемещением и пятью позициями.

В главе 1.3 завершены восемь центральных CU-опытов на обеих моделях при p4/p5 и четыре временных контроля; подготовлены сейсмограммы и анимации скорости и энергии. Максимальная p-разность полного окна на приёмниках не ближе 20 м от источника — 0,007502426%, а на всей линии вертикальные компоненты отличаются на 3,873174–4,169870%. Оба варианта №65 выполняют рабочие критерии far20; оба варианта №12404 не выполняют требование dt/p≤0,2 при малых относительных поправках. Это внутренние критерии протокола, не заданный пользователем допуск. Сам узел источника сохранён в записи; безусловная сходимость всей линии не заявляется. Остальные положения источника отложены пользователем. Подробности и границы вывода — в [реферате 1.3](dev_1_3_point_source_summary.md).

Дополнительная проверка p3 завершена отдельной серией: четыре основных опыта и четыре временных контроля на тех же геометриях. Максимальная разность p3/p5 полного окна far20 — 0,159628%, позднего окна — 1,561630%; по полной линии вертикальная разность достигает 9,399834% и сосредоточена преимущественно в источнике. Рабочие критерии полного окна far20 пройдены по обеим опорам, но у №12404 запас геометрического эффекта в Vy снижается до 4,19 при ориентире 5. Для основной программы сглаживания рекомендовано сохранить p4. Прежние результаты не перезаписаны; подготовлены новые сейсмограммы и анимации p3/p4.

Исторические JSON и хеши сохранены без переписывания. [Карта переноса](docs/migration/README.md) связывает прежние пути в TrySEMGPU с текущими. Правила ведения исследования — [AGENTS.md](AGENTS.md).

# Скрипты этапов

Запускать утилиты из корня проекта через `.venv/bin/python -m scripts.<этап>.<модуль>`. Дневники `dev_*.py` остаются императивными; вычислительные CLI в этом каталоге имеют отдельные `main()` и не исполняются при импорте.

## 1.1. Предобработка

- `dev_1_1_preprocessing.prepare_data` — исходные ZIP/тексты → проверенные NPZ, обзорные и массовые PNG.
- `dev_1_1_preprocessing.dataset_statistics` — полный пересчёт диапазонов VP/VS, количества материалов и контрольных сумм из текста или NPZ.

## 1.2. Сглаживание

- `dev_1_2_smoothing.vectorization_probe` — проба общего графа и сплайнов.
- `dev_1_2_smoothing.select_layered_model` — выбор №12404 из бинарного датасета.
- `dev_1_2_smoothing.pilot_mesh`, `pilot_geometry_plot`, `pilot_verify_order`, `pilot_stability` — Q2-геометрия, рисунки и проверки выбранного порядка.
- `dev_1_2_smoothing.pilot_run`, `pilot_windows`, `windows_tensor_probe` — историческая CEED-линия и Windows-инструменты; prefix/DLL задаются явно.
- `dev_1_2_smoothing.pilot_cu_run` — native CU-пара №12404.
- `dev_1_2_smoothing.pilot_compare`, `pilot_cu_compare` — проверка и сопоставление записей; CU-постобработка поддерживает карту перенесённого provenance.
- `dev_1_2_smoothing.model65_geometry`, `model65_mesh`, `model65_geometry_plot`, `model65_stability`, `model65_run`, `model65_compare` — отдельная постановка №65; сеткопостроение требует extra `meshing` и Gmsh.

Общие утилиты: `project_paths.py` — корень, пути этапов, шрифт и проверка исторических хешей; `reporting.py` — типизированное чтение компактных метрик для дневников. Рабочие скрипты не импортируют `research` из TrySEMGPU.

## 1.3. Точечные источники

- `dev_1_3_point_source.preflight` — лёгкая проверка GLL-узлов и контрольных VP/VS; запись нового JSON в `data/`, по умолчанию без перезаписи. Решатель и сеткопостроитель не импортируются.
- `dev_1_3_point_source.physics` — типизированные соглашения источника, времени, продолжения материала, массового демпфирования и работы силы.
- `dev_1_3_point_source.check_physics` — адресные CPU-проверки этих соглашений.
- `dev_1_3_point_source.mesh`, `check_mesh` — четыре расширенные Q2-сетки, сертификаты и GLL-вложения. `mesh` поддерживает p3/p4/p5; исторический `check_mesh` проверяет p4/p5, отдельные p3-свидетельства сохранены в `p3_preflight_v1`. Старые массивы не изменяются.
- `dev_1_3_point_source.stability` — консервативная оценка шага с αM и ABC по фактической сетке.
- `dev_1_3_point_source.run`, `check_run` — отдельный native-опыт, потоковые поля и контроль расписания. `--field-layout compact` сохраняет Vx/Vy и две плотности энергии в float64 без полевых U и дублирующих узловых энергий. `--no-fields` подходит для дополнительных временных контролей.
- `dev_1_3_point_source.batch` — по умолчанию только новый план; `--run` последовательно выполняет его с проверками места и завершённых outputs. Текущий пользовательский объём задаётся `--sources 350`; остальные источники отложены.
- `dev_1_3_point_source.batch_p3` — отдельный план четырёх центральных p3-опытов и четырёх временных контролей на прежних Q2-сетках. Основные K64/224 совпадают с опорной серией, контролям соответствуют K128/448. `--run --kind raster|curved` исполняет выбранную очередь при общем плане восьми заданий; `--verify` проверяет все восемь завершённых результатов без решателя. Повторное создание плана и перезапись неполных каталогов запрещены.
- `dev_1_3_point_source.compare`, `animate` — отчёты, сейсмограммы и MP4 только по завершённым массивам. Синтетические/короткие проверки отделяются явным `--allow-short` и не считаются двухсекундной серией.
- `dev_1_3_point_source.source_diagnostic` — локализация различия порядков по приёмникам и проверка одинаковой истории силы, включая t=0; источник не удаляется из исходной записи. Поддерживает `--value/--reference`, прежние `--p4/--p5` остаются совместимыми.
- `dev_1_3_point_source.acceptance` — проверка рабочих p/dt-критериев вне радиуса 20 м с отдельным выводом метрик всех приёмников, неизвестных результатов и ограничений; геометрический эффект сопоставляется с абсолютными p/dt-поправками.
- `dev_1_3_point_source.p3_report` — отдельные проверки p3/p4 и p3/p5 с собственным временным контролем p3. Финальный отчёт требует 16 завершённых входов: восемь новых p3 и восемь прежних основных p4/p5. Раскрывает полную линию, far10/far20, позднее окно, локализацию источника и запас геометрической разности. Прежний `acceptance` и его результаты не изменяет.

## 1.4. Подготовка сервера

- `dev_1_4_server_preparation.collect` — явный SSH-аудит с текущей рабочей станции, только чтение, новый обязательный выходной каталог в data главы. Передаёт probe.py через stdin и сохраняет ответы и SHA256 локально; на сервер скрипт не устанавливается. Не запускается из дневника.
- `dev_1_4_server_preparation.probe` — ограниченные по времени запросы оборудования/состояния и подсчёт выделенных блоков домашнего каталога при nice=19 и idle I/O; без sudo, решателя, бенчмарков, установки или изменения конфигурации. Не пересекает файловые системы и символьные ссылки, отмечает неполный обход. Глобальные квоты UID и объём Docker этим обследованием не устанавливаются.
- `dev_1_4_server_preparation.storage_probe` — дополнительный явно запрошенный аудит размеров: собственные подкаталоги и крупные файлы, только суммарные объёмы других домашних каталогов и видимых системных данных. Передаётся серверному python3 через SSH stdin, без установки; низкий приоритет и тайм-ауты, агрегированные ошибки доступа. Не читать как точные квоты пользователей и не использовать как автоматический список удаления.

`build_notebooks.py` — конвертация четырёх дневников штатным py2jupyter с проверкой формата и обратного AST; `--execute` выполняет отчётные ячейки, `--diary dev_1_4_server_preparation` выбирает только главу подготовки сервера без изменения прежних ноутбуков.

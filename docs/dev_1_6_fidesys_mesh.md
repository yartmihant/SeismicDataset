# Криволинейные сетки ECVB в Fidesys 10.0

Генератор строит сетку основной области 1400×700 м для указанных экземпляров ECVB. На верхней стороне вершины стоят при x=0,10,…,1400 м, а средние узлы QUAD8 — при x=5,15,…,1395 м. Начальный целевой размер внутри области равен 10 м. Каждый связный регион получает свою поверхность и блок с одинаковым ID. Готовый FC хранит материалы блоков, вход SEMGPU2 содержит ту же геометрию и поэлементную карту свойств. PML и узлы p6 создаются при подготовке конкретного расчёта.

## Модель в формируемом датасете

Единица обработки — исходный номер ECVB. Готовая модель лежит в `data/dev_1_6_fidesys_mesh/dataset_v1/NN000-NN999/ECVBxxxxx/`. Тысячные диапазоны в пути служат только для организации файлов. Одна и та же команда обрабатывает отдельные номера и интервалы, включая пять пилотных номеров.

| Файл | Содержимое |
|---|---|
| `cartesian.npz` | Исходные ячейки 70×70, исходные Vp и Vs в м/с, карта регионов, координаты границ ячеек. Строка 0 сверху, столбец 0 слева. В архивной постановке Δx=Δy=10 м, в расчётной Δx=20 м и Δy=10 м. Преобразование координат сохраняет значения скоростей. |
| `geometry.jou` | Журнал построения плоских границ и поверхностей в Fidesys из пустой сессии. Точное исходное описание полюсов, узловых векторов, ориентации контуров и смежности хранится рядом в `geometry.json`. |
| `ECVBxxxxx.fc` | Основная область 1400×700 м, плоские QUAD8. Номер растрового региона, поверхности, блока и материала совпадает. Каждому блоку назначены собственные Vp и Vs и общая ρ=1000 кг/м³. |
| `sem_input.npz` | Та же основная область в тензорном Q2-представлении. Девятый узел вычислен по восьми узлам QUAD8 так, что геометрическое отображение совпадает. Хранятся связность, карта материала, регионы и номера элементов FC. |
| `manifest.json` | Числовой ID исходной модели, исходные SHA256, имена и SHA256 всех представлений, метрики сетки, результаты воспроизведения CAD и проверки подготовки SEM. |

Сборка и проверка пилотов из корня проекта:

```bash
export PYTHONPATH=/home/antonov/Work/Tools/Lib/FCModel/src
.venv/bin/python -m scripts.dev_1_6_fidesys_mesh.dataset \
  --ids 0 65 12404 15000 29999 --mesh-cache data/dev_1_6_fidesys_mesh/pilot_v2
```

Журнал проверен в Linux Fidesys 10.0. Внутри находятся точные кривые ACIS и читаемые полюса и узловые векторы. Штатный playback использует GNU `base64` и `mktemp` для развёртывания встроенного ACIS, создаёт поверхности и задаёт интервалы. Пользователь может открыть один `.jou` в чистой сессии и затем выполнить команды построения сетки. При запуске журнала на Windows потребуется адаптировать этот шаг.

Для новых моделей контроллер принимает `--ids ID ...` или `--range FIRST LAST`, границы включены. Аргумент `--mesh-cache` необязателен. По нему читаются проверенные сетки прежнего формата. При отсутствии сетки контроллер строит её по исходным полям. Каждая модель публикуется переименованием временного каталога после проверок. При повторном запуске для уже готового номера сверяются исходные SHA, версия формата, запрошенный минимум scaled Jacobian и контрольные суммы файлов. Такое обращение возвращает `verified_existing`.

## Сборка расчётной модели

На диске оба сеточных представления ограничены основной областью. Контроллер перед расчётом наращивает PML на 350 м влево, вправо и вниз. Каждое граничное ребро продолжается по нормали с материалом своего элемента, нижние угловые квадраты наследуют угловой материал. В месте выхода наклонного интерфейса на границу допускается излом. Верх остаётся свободным. На полной области 2100×1050 м контроллер строит узлы GLL p6 в той же Q2-геометрии и назначает первым 1261 узлам весь верх слева направо. Геометрическое отображение остаётся квадратичным. Массивы узлов и связности p6 существуют в памяти на время подготовки и расчёта.

```python
from pathlib import Path
from scripts.dev_1_6_fidesys_mesh.sem_input import P64S, P67S, prepare_p6

path = Path("data/dev_1_6_fidesys_mesh/dataset_v1/00000-00999/ECVB00000/sem_input.npz")
prepared = prepare_p6(path, P67S)  # Для четырёх опытов передать P64S.
```

Для выбранного фиксированного решателя создают `model = SGModel(prepared.mesh, solver)`, затем вызывают `model.add_physics(prepared.material)` и `model.add_physics(prepared.pml)`. Источники встроены в backend. Массив `prepared.receiver_nodes` задаёт порядок 140 приёмников. Контракт сборки [seismic_p64s_v1](runtime_sources/seismic_p64s_v1/) задаёт для полного верха диапазон x=−350…1750 м, 210 рёбер по 10 м и нумерацию 0…1260. При p6 угловые, промежуточные и центральные узлы каждого ребра расположены в точках GLL. Для приёмников x=5,15,…,1395 м глобальные ID равны 213,219,…,1047. Для источников x=100,300,500,700,900,1100,1300 м глобальные ID равны 270,390,510,630,750,870,990. p64s использует первые четыре. В асимметричной ECVB три правых источника требуют собственных опытов, поэтому для семи сейсмограмм выбирают p67s. Проверка сопоставляет каждую координату полного верха с профилем native-сборки с абсолютным допуском 10⁻⁹ м.

## Приёмка формата на пяти моделях

Исходные Vp и Vs побитово совпали с полями из ZIP. Независимое чтение FC подтвердило состав регионов, соседства, карту материала, все восемь общих с QUAD8 точек каждого Q2 и координаты достроенного центра. В №00065 два верхних включения сохранили размеры 640×70 м и 540×70 м. Повторный `mesh surface all` с последующим экспортом QUAD8 после штатного воспроизведения журналов №00065 и №15000 дал побитовое совпадение всей секции `mesh` соответствующих FC. Свежая сборка №00065 из ZIP без кэша воспроизвела растр, точное описание CAD, материализованный FC и вход SEMGPU2 побитово.

На каждом пилоте проверены расширенное поле материала, положительность якобиана, нумерация GLL, четыре и семь фиксированных источников текущей сборки и приёмники. Максимальная ошибка абсциссы по полному верхнему ряду — 4,55·10⁻¹³ м. Проверка выполнена на CPU до передачи массивов в CUDA. Повторная команда подготовки распознала все пять готовых номеров по SHA256.

Пять полных каталогов занимают 12,93 МБ. Экстраполяция на 30 000 при том же среднем размере даёт около 77,6 ГБ (72,2 ГиБ) только для перечисленных артефактов. Для пяти сжатых SEM-входов хранение только ядра сэкономило 1,31 МБ по сравнению с сохранением Q2 вместе с PML (27% от размера полных Q2-входов). [Числовое свидетельство со ссылками на манифесты](../data/dev_1_6_fidesys_mesh/dataset_pilot_checks_v1.json).

## Ранний генератор сетки основной области

Из корня проекта для пяти пилотов на этой машине:

```bash
export PYTHONPATH="/home/antonov/Work/Tools/Lib/FCModel/src"
.venv/bin/python -m scripts.dev_1_6_fidesys_mesh.generate --ids 0 65 12404 15000 29999
```

Для диапазона служит `--range FIRST LAST` с включёнными границами 0…29999. Каталог серии задаётся `--out`. Параметр `--fidesys` задаёт корень установки, по умолчанию /home/antonov/.bin/CAE-Fidesys-10.0. Внешний интерпретатор принадлежит проекту. Для команд CAD и экспорта генератор сам запускает встроенный в Fidesys Python 3.8. Предполагается та же рабочая локальная установка Fidesys, на которой выполнены пилоты.

В каталоге каждой завершённой модели находятся ECVBxxxxx.fc, geometry.json, mesh_export.jou и result.json. Команды из mesh_export.jou можно использовать в препроцессоре после подготовки соответствующей геометрии с размерами поверхностей и интервалами верха. Встроенный обработчик задаёт точные сплайны через полюса и узловые векторы, приводит нормали к +z и назначает интервалы верха. Для повторения с нуля достаточно исходного VP/VS и команды генератора.

## Геометрия и проверки

Для сквозных слоёв генератор использует существующую аппроксимацию глубин кубическими сплайнами, для общей топологии — общие границы растровых регионов с закреплением прямоугольных и выраженных углов. Порядок геометрии задаётся командой `block all element type QUAD8`, проекция средних узлов — `set node constraint on`, вид экспортируемого плоского элемента — постановкой dim2 planestrain. Все блоки объединяют элементы одной поверхности. Подготовка модели не вызывает волновой решатель.

FCModel перечитывает конечный файл. По восьми узлам восстанавливается серендипова квадратичная карта. При записи в тензорном виде её центральный узел равен половине суммы четырёх средних узлов рёбер минус четверть суммы углов. По коэффициентам Бернштейна проверяется положительность det J на всей площади каждого элемента. Отдельно проверяются ориентация, конформность с совпадением идентификаторов средних узлов, состав блоков, граф соседств, граница области, общая площадь и 140 верхних интервалов.

Качество формы оценивается в 7×7 узлах GLL каждого элемента. Параметр `--min-scaled-jacobian` задаёт инженерный порог для локального перестроения. По умолчанию он равен 0,05, при 0 действует только проверка положительности и остальные геометрические проверки. При отказе сертификата генератор выбирает регионы с проблемными элементами. При слишком низком scaled Jacobian перестраивает регион худшего элемента. Целевой размер соответствующей поверхности сначала снижается до 7,5 м, при повторном отказе в том же регионе — ещё в 1,5 раза. Допускаются три повторные попытки. Остальные поверхности сохраняют исходный целевой размер, граничная сетка согласуется при каждом построении.

Средние узлы межматериальных рёбер проверяются относительно соответствующего CAD-интерфейса с допуском 0,0001 м. Расстояние ребра до CAD измеряется дополнительно в 21 точке каждого ребра. Это односторонняя выборочная оценка. Её максимальное значение и координаты записываются в result.json. Пользователь принял наблюдавшийся пилотный максимум 0,53714 м. Это расстояние между ребром QUAD8 и соответствующим CAD-сплайном. Отклонение сглаженной границы от исходной растровой ступеньки измеряет другую величину.

Готовая модель публикуется после проверки. При повторном обращении к ID генератор сверяет контрольные суммы VP/VS, описания границ и FC, версию схемы и требуемый порог формы. Диагностика отказов сохраняется в failures/. По умолчанию ошибка останавливает команду, с `--keep-going` обрабатываются остальные ID и возвращается ненулевой код при наличии отказов. В пилотной серии использованы пять ID; доля успеха для всех 30 000 по ним не установлена.

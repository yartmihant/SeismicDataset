## Сила, направление и демпфирование

`SGPhysicsModel(name, 20200, mesh, 0, node_ids, values, time=SGPhysicsTimeData(t_begin, t_end, sample_count, interp_code))` задаёт `N_FORCE_DYNAMIC`. Для одного источника `node_ids.shape=(1,)`, `values.shape=(sample_count,1,2)`, компонент X равен нулю, компонент Y содержит силу. Это уже сила на узел на единицу толщины, а не плотность силы: множитель площади, квадратурного веса или массы добавлять нельзя. В CU масса умножает только гравитацию: `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/kernels/response.cu:193`. Формат модели и времени определён в `model/physics.py:20` и `model/physics.py:36`.

В прежнем пилоте верх имел координату Y=700 м, положительная ось Y направлена вверх, поэтому сила была отрицательной: `scripts/dev_1_2_smoothing/pilot_run.py:143` и `scripts/dev_1_2_smoothing/pilot_run.py:271`. Для главы 1.3 удобно сохранить направление Y вверх, сдвинуть верх на Y=0 и основной квадрат в Y∈[−700,0]; тогда импульс вниз остаётся отрицательным. При другом выборе оси необходимо одновременно преобразовать геометрию, силу и компоненты регистрируемого поля.

`N_MASS_DAMPING_STATIC=30001`, пространство N=0, массив значений `(n_nodes,1)` принимает коэффициент α в с⁻¹. Решатель сам формирует диагональное демпфирование Cᵢ=αᵢMᵢ: CU `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/secondary.cpp:138`, CEED `solvers/lin_elast_2d_tenzor_newmark_kim_ceed/backend/secondary.cpp:205`. Передавать αM вместо α ошибочно. Допустим профиль α=αmax[(d_left/L)²+(d_right/L)²+(d_bottom/L)²], где расстояния положительны только снаружи физического квадрата; в углах вклады складываются. Силу демпфирования решатель направляет против скорости.

`ABC=32000` задаётся в пространстве BOUNDARY=2 через `SGPhysicsModel.from_entity_values` со значениями `[ρVp,ρVs]` для каждой внешней нижней/боковой грани. Пример сборки: `scripts/dev_1_2_smoothing/pilot_run.py:259`. Верх всего расширенного домена остаётся свободным; внутренние границы физического квадрата не должны попадать в ABC. Коэффициент αmax и эффективность сочетания слоя с ABC требуют отдельной проверки отражений; наличие API этого не доказывает.

## Регистрация непосредственно в узлах

`SGReceiverModel.from_positions(name, mesh, 0, node_ids, comp_codes, begin_tact=0, end_tact=N, stride=k, handler=handler, frame_shape=(n_nodes,))` снимает значения с глобальных узлов без поиска элемента и интерполяции; см. `model/receiver.py:73`. Метод `from_points` предназначен для интерполяции в положительном P-пространстве и не подтверждает наличие физического узла в заданной координате. Для источников и приёмников сначала требуется однозначный поиск совпадающих координат с допуском, затем использование полученных глобальных идентификаторов.

Коды компонентов: UX=2, UY=3, VX=4, VY=5, EXTERNAL_FORCE_X=12, EXTERNAL_FORCE_Y=13, MASS=8, SIZE=9, KINETIC_ENERGY=100, ELASTIC_ENERGY=101, KINETIC_ENERGY_DENSITY=110, ELASTIC_ENERGY_DENSITY=111. Определения: `solvers/lin_elast_2d_tenzor_newmark_kim_cu/_native.pyi:179`. Энергетические каналы разрешены в N-пространстве, но не MAIN; проверки: CU `backend/receivers.cpp:17`, CEED `backend/receivers.cpp:6` внутри соответствующего каталога решателя. Кадр имеет порядок `(n_components,*frame_shape)`, см. `model/receiver.py:242`.

Для тестовой анимации получать `[VX,VY,KINETIC_ENERGY,ELASTIC_ENERGY,KINETIC_ENERGY_DENSITY,ELASTIC_ENERGY_DENSITY]` на `arange(mesh.nodes_coords.shape[0])`; скорость отображать как sqrt(VX²+VY²), энергию как сумму кинетической и упругой частей. Для сравнимой цветовой шкалы на разных сетках отображать плотность энергии, а узловую энергию хранить для суммирования. Все глобальные узлы, включая поглощающий слой, записывать один раз. Сохранять координаты, связность, порядок, маску физической области и единицы вместе с массивами. Сглаженную картинку на материальном интерфейсе не трактовать как единственную локальную плотность энергии по обе стороны интерфейса.

Кинетическая энергия узла равна 0.5Mᵢ(Vxᵢ²+Vyᵢ²); упругая часть вычисляется из 0.5 ε:σ в квадратуре, переносится в узлы и суммируется из примыкающих элементов: CU `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/kernels/receiver.cu:24` и `:85`; CEED `solvers/common/ceed/actions.h:118` и `:283`. На общей границе элементов это уже собранная энергия глобального узла: повторно суммировать её по `mesh.strata[1].p_nodes` нельзя. Полная энергия всей области получается суммой каналов 100+101 по уникальным N-узлам. Плотности 110/111 делятся на собранную узловую меру SIZE. Разбиение полной энергии между физическим квадратом и слоем по маске координат неоднозначно на их общем интерфейсе; для строгого баланса по подобластям нужны интегралы по элементам.

## Одинаковая сила и диагностика работы

Канал EXTERNAL_LINEAR_WORK=102 не является накопленной работой: реализация возвращает текущий скалярный продукт u·F. Нельзя использовать его как введённую энергию. Это явно видно в CU `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/kernels/receiver.cu:26` и CEED `solvers/common/ceed/actions.h:284`.

Работу вычислять как временной интеграл P(t)=F(t)·v_source(t) по всему согласованному интервалу возбуждения, включая оба знака мощности. Для одного вертикального источника P=FyVy. Записывать с источника VY=5 и EXTERNAL_FORCE_Y=13 на каждом внутреннем шаге; затем интегрировать, например, трапециями и повторить с вдвое меньшим шагом, чтобы оценить погрешность интеграла. Энергия, оставшаяся в поле после ухода волн в демпфирующий слой, не равна введённой работе. Положительную часть P нельзя подставлять вместо подписанного интеграла без отдельного изменения определения нормировки.

В окончательной постановке используется одна и та же физическая амплитуда силы Рикера для всех разрешений сетки. Энергетическая перенормировка не применяется. Фиксированная узловая сила исключает искусственную зависимость нагрузки от площади или массы узла, но не навязывает совпадение мгновенной мощности или интегральной работы. Их различие между сетками следует сохранять как диагностический результат, а не устранять изменением амплитуды.

Для проверки p=4→p=5 сопоставлять результаты при одной физической амплитуде источника. Работа источника полезна как дополнительный контроль вместе с балансом энергии и погрешностью временного шага. Если пять источников запускаются одновременно, работа содержит перекрёстные вклады, поэтому её нельзя получать простым сложением энергий пяти отдельных выстрелов.

## Расписание без потери внутренних шагов

В интерфейсе приёмник вызывается по тактам, а не по произвольным внутренним шагам. Если требуется диагностировать работу на каждом внутреннем шаге, выбрать `steps_count=2000*K`, `steps_per_tact=1`, где целое K удовлетворяет фактическому ограничению устойчивости и требуемой временной точности. Тогда внутренний шаг равен 0.001/K с, такт совпадает с шагом, источник регистрируется `stride=1`, сейсмограмма — `stride=K`, все узлы — `stride=10*K`; `begin_tact=0`, `end_tact=2000*K`. Получаются ровно 2001 срез сейсмограммы за 0…2 с и 201 кадр поля через 0.01 с. Правила временной сетки находятся в `solvers/common/time_grid.py:17` и `:193`; цикл CU по внутренним шагам и тактам — `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/runtime.cpp:204`.

В нулевом такте CU публикует заданное начальное состояние и нулевую response; при нулевой начальной скорости начальная мощность всё равно равна нулю. Силовые каналы после шага содержат внешнюю силу, собранную на времени этого шага, скорость — итоговую после коррекции: `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/stepping.cpp:243`. Произведение даёт дискретную оценку физической мощности; оно не заявляется точным энергетическим инвариантом схемы Newmark–Kim. Редкая запись через 1 мс без проверки ошибки для точной диагностики работы недостаточна без проверки ошибки.

Рекомендуется копировать принятый кадр внутри обработчика и немедленно сохранять поля в заранее выделенный массив/файл, а не удерживать несколько полных копий серии. Работа с `solver.solutions` после завершения даёт конечное состояние, но не историю; для истории использовать приёмники. Запись источника каждый шаг повышает расходы на обмен CPU/GPU; это следует замерить в тестовом прогоне, не ослабляя контроль интеграла без проверки.

Далее пути указаны относительно `solvers/lin_elast_2d_tenzor_newmark_kim_cu/backend/`. Начальные U/V/A выделяются нулями в `solver.cpp:129` и `data.hpp:41`; `preparation.cpp:9` рассматривает только статические силы, пропуская динамические на строке 13, и не устанавливает начальное ускорение из динамического Рикера. При запуске `stepping.cpp:148` переносит заданное состояние, а строка 149 обнуляет response. `runtime.cpp:204` явно публикует нулевой такт до первого численного шага; канал FY=13 читает response в `kernels/receiver.cu:21`. Следовательно, FY(0)=0 — значение ещё не собранного канала, а не аналитическое значение Рикера в начальной точке.

Этот нюанс касается также начального ускорения, поэтому его нельзя описывать только как особенность записи. Хотя таблица силы сначала загружается при t=0 (`stepping.cpp:121`), первый шаг вызывается уже при t=Δt (`runtime.cpp:209`), выполняет predict → assemble_force_response(Δt) → correct (`stepping.cpp:243`), а динамические значения повторно вычисляются на времени этого шага (`stepping.cpp:129` и `:205`). При фактических β=0 и γ=1/2 (`constants.hpp:16`) и нулевых U/V/A первое обновление источникового узла имеет u₁=0, v₁=Δt·Fy(Δt)/(2M), a₁=Fy(Δt)/M; это непосредственно следует из `kernels/step.cu:40` и `:48`. Начальное ускорение Fy(0)/M автоматически не формируется. В сохранённом опыте `central_cu_v1/12404/raster/p4/x350/source_history.npz` первый шаг Δt=1,5625·10⁻⁵ с дал Fy(Δt)=9,980741583491606·10⁻⁹ Н/м и Vy(Δt)=6,23796348968154·10⁻¹⁶ м/с, что согласуется с этой формулой для источниковой массы 125 кг/м с относительным остатком около 1,15·10⁻¹³.

Аналитическое Fy(0)=+9,84949251974796·10⁻⁹ Н/м составляет около 9,85·10⁻⁹ от амплитуды 1 Н/м. Проверка двенадцати завершённых историй обнаружила это начальное исключение; для t>0 максимальное отличие зарегистрированной силы от Рикера не превышает 1,5543122344752192·10⁻¹⁵ Н/м, главный пик равен −1 Н/м при t=0,05 с, а p4/p5-истории силы внутри каждой пары одинаковы побитово. Замена только зарегистрированного FY(0) не изменила бы вычисленную трапециями работу, поскольку Vy(0)=0, но не восстановила бы отсутствующее согласование начального ускорения. Влияние этой начальной конвенции на полное решение отдельно не измерялось; малость хвоста не является строгой оценкой ошибки. Решатель, запускатель и исторические массивы не изменялись, повторные расчёты для этого уточнения не выполнялись.

# Устройство CUDA-решателя p67s

Python-фасад использует `FixedOrderSolver`. CMake собирает собственный модуль `_native` с таблицами W/V/G штатного ALine p6. Протокол приёмников, терминальных событий, команд SAVE/COMPLETE/ABORT и очередь обработчиков используют тот же цикл запуска, что и семейство фиксированных порядков. [Сборка](../../CMakeLists.txt), [реализация](../../src/semgpu2/solvers/lin_elast_2d_seismic_newmark_kim_p67s_cu/backend).

Из тех же исходников CMake собирает `p64s` и `p67s` в отдельные модули. Константа сборки `SEMGPU2_SEISMIC_SHOT_COUNT` задаёт число опытов (4 или 7), число групп строк, глубину сетки CUDA для шаговых ядер и размер запуска встроенного источника. Спектральная проба в обеих сборках использует один пробный вектор. [Четыре источника, поля и приёмники p64s](LIN_ELAST_2D_SEISMIC_NEWMARK_KIM_P64S_CU_EXTERNAL2.md).

`compile()` проверяет связность MAIN, наличие диапазона номеров `0…1260` верхнего ряда и выделяет поля N и MAIN. `mesh()` проверяет координаты всего верхнего ряда с абсолютным допуском \(10^{-9}\) м по каждой оси, затем вычисляет меру и обратный якобиан для каждой Q-позиции и собирает узловую меру. Функция `source_profile::node(shot)` возвращает один из номеров `270, 390, 510, 630, 750, 870, 990`. Есть один комплект этих полей, одной связности и одной диагональной массы на семь опытов.

При подготовке прежней сетки `with_leading_nodes` переставляет узловые координаты и теги, переводит связность в новые N-номера и возвращает соответствие старых номеров новым. Сценарий применяет это соответствие к N-приёмникам и внешним узловым данным до создания модели.

`prepare()` принимает только активные экземпляры 11000 и 31100. Неактивная пользовательская физика игнорируется по общему SolverAPI. Решатель проверяет покрытие MAIN материалом, вычисляет в Q плотность и параметры Ламе, суммирует пересекающиеся профили слоя. Носители обычного и PML-материала образуют разбиение MAIN. Профиль с нулевым значением в отдельной точке сохраняет принадлежность элемента к слою. Спектральная проба действует обычным упругим оператором на всех элементах и использует одну пару компонент пробного вектора. После выбора фактического шага в слое доступны плотность, параметры Ламе, два профиля, два множителя затухания и два веса интегрирования. Для малых и нулевых профилей действует та же предельная ветвь, что и в p6. [Оператор и рекурсия](CARTESIAN_PML2.md)

После подготовки временной сетки `prepare()` вычисляет один FP64-образец встроенного Рикера на каждый внутренний шаг. Без ограничения шагов для секундной задачи это 9000 значений. При `max_steps` создаётся только достижимый префикс. Перед циклом расчёта таблица один раз копируется на GPU. Индекс очередного отсчёта равен числу уже завершённых внутренних шагов. Ядро источника добавляет вертикальное значение образца в один из фиксированных верхних узлов для каждого shot-слоя. Источник не входит в спектральную пробу. Вызов `SAVE` сохраняет состояние после уже выполненных шагов, а при последующем `prepare()` таблица источника строится заново по новому абсолютному интервалу времени.

Перед запуском решатель упаковывает каждый материал в порядке его элементов и локальных Q-позиций. Обычный материал имеет строки `rho, lambda, mu`, материал PML — `dx, dy, ax, ay, bx, by, rho, lambda, mu`. Упругие строки обоих материалов берутся из текущего публичного поля `materials[MAIN]`, поэтому запись в это поле после `prepare()` действует и внутри слоя. При отсутствии PML узлы квадратуры материала уже идут в порядке MAIN.

В начале каждого `run()` решатель читает текущие массы из `materials[N]` и вычисляет обратные значения для всех узлов. Если все они конечны и положительны, в единственный буфер массы на GPU загружаются обратные значения, и корректор умножает на них узловую силу. Если хотя бы одно обратное значение непредставимо или неположительно, весь запуск использует исходные массы и деление. У спектральной пробы собственный контекст с исходными массами.

Матрица производных фактора p6 содержит 49 коэффициентов FP64 в константной памяти. Первая группа из 49 потоков каждого блока обычного или PML-материала копирует её в 392 байта разделяемой памяти. После общего барьера потоки читают разные коэффициенты для градиентов и транспонированного градиента. Геометрические коэффициенты берутся из полей MAIN для каждой Q-позиции.

На внутреннем шаге ось опыта отделена от номера глобального узла. Предиктор и корректор обрабатывают связанные u/v/a выбранного направления. Упругий оператор собирает силу на обычных элементах. На элементах слоя отдельное ядро вычисляет упругий поток, обновляет четыре локальные истории выбранного опыта и прибавляет поправку PML к потоку до применения транспонированного градиента. Инерционная поправка входит в ту же узловую сборку. Затем встроенный источник добавляет одно значение в вертикальную строку соответствующего опыта. Масса, материал и внутренняя геометрия могут меняться по пространству.

Первый шаг такта начинается с отдельного предиктора. Если в том же такте предстоит ещё один шаг, корректор сразу вычисляет предсказанные перемещения и скорости следующего шага в регистрах. На границе такта или при достижении `max_steps` он записывает скорректированное состояние, доступное приёмникам и команде `SAVE`. При `check_finite_each_step=True` каждый шаг завершается отдельной коррекцией и проверкой.

Адреса узлов, элементов и Q-позиций принадлежат одной сетке. У `solutions[0]`, внутреннего отклика и `pml_history` каждому опыту принадлежит непрерывная группа строк. Приёмник использует общие адреса и веса, а код компоненты определяет строку скорости. На `SAVE` на host переходят узловые состояния и история всех семи опытов.

Поклассовые диапазоны VP/VS и точных количеств материалов сохранены в [dataset_statistics.json](presentation/dataset_statistics.json), новые волновые метрики — в [pilot_cu/comparison/report.json](pilot_cu/comparison/report.json). Исторические серии и их отчёты сохранены отдельно.

## Состав Git-версии

В Git сохраняются сценарии, протоколы, отчёты, компактные JSON с геометрией и метриками, итоговые иллюстрации и [презентация](presentation/seismic_dataset_sem_review_20261105.pptx). Полный исходный набор `src/`, 60 бинарных блоков `binary/*.npz` и 60000 изображений `previews/A/EFVB/` и `previews/A/ECVB/` остаются локально и исключены через `.gitignore`. Общие manifest и небольшие обзорные листы сохранены как описание формата, шкалы и выполненной обработки.

Расчётные массивы полей/сейсмограмм, сеточные NPZ/MSH и промежуточные preview/dry-run также не входят в Git. Исключения для NPZ ограничены тремя небольшими файлами: `pilot_geometry/selected_model.npz`, `pilot_geometry/frozen_q2_geometry.npz` и `model65/geometry/model65.npz`; это две выбранные модели и фиксированная геометрия первого опыта, а не основной датасет. Журналы и метаданные завершённых расчётов, включая manifest с контрольными суммами, описывают исходный локальный эксперимент: упомянутые в них тяжёлые файлы нужно восстановить отдельно для полного повторного аудита или пересчёта метрик. Массовые команды подготовки требуют исходных ZIP, а не одного клона репозитория.

## Бинарные данные

`prepare_data.py convert` читает оба исходных ZIP-архива EFVB и ECVB из `src/` напрямую, без повторной распаковки и зависимости от вложенности распакованных папок. Ожидаются ровно 30000 пар с ID 00000–29999 в каждом классе. Исходные файлы сохраняются; распакованные копии не являются входом этой команды.

В `binary/` создаются сжатые NPZ, по умолчанию по 1000 моделей на файл. Ключи: `ids` — int64, форма `(N,)`; `vp`, `vs` — float64, форма `(N, 70, 70)`, единицы м/с. Первая строка соответствует верху среды; столбцы идут слева направо. Значения относятся к ячейкам 10 × 10 м. Float64 сохраняет результат разбора исходных десятичных чисел без дополнительного округления в float32; текстовое оформление не сохраняется.

Каждый записанный блок повторно открывается с `allow_pickle=False`; значения и dtype всех массивов сравниваются с входными массивами точно. Проверяются пары ID, форма, конечность, положительность скоростей и положительный объёмный модуль изотропного материала. Это проверка данных, а не валидация будущего численного решателя.

`binary/manifest.json` записывается только после успешного завершения всего прохода. Он содержит глобальные и поклассовые диапазоны, описание осей, SHA256 каждого NPZ и совокупный SHA256 исходных файлов. Незавершённый каталог без manifest не является готовым датасетом. Повторный запуск конвертации в завершённый каталог запрещён; для новой версии задаётся другой `--output`.

## Цветовые пробы

`prepare_data.py previews` создаёт в `previews/` отдельные PNG 350 × 350 для моделей 00000, 15000 и 29999 обоих классов. Увеличение nearest-neighbour: одной ячейке соответствуют ровно 5 × 5 пикселей. Исходная ориентация сохраняется. `comparison.png` — обзорная таблица; `legend_*.png` — двумерные легенды.

Для всех изображений используются одни пределы, вычисленные по всем 60000 моделям обоих классов: `p=(vp-vp_min)/(vp_max-vp_min)`, `s=(vs-vs_min)/(vs_max-vs_min)`. VP и VS имеют свои физические пределы, общие между моделями и классами. Локальной нормировки, квантильного отсечения и сглаживания нет.

- A (`rg`): RGB = `(p,s,0)`, VP — красный канал, VS — зелёный.
- B (`rb`): RGB = `(p,0,s)`, VP — красный канал, VS — синий.
- C (`bivariate`): билинейное смешение четырёх углов: низкие VP/VS — светлый `(245,245,240)`; высокий VP — оранжевый `(230,130,45)`; высокий VS — голубой `(65,155,210)`; оба высокие — тёмно-фиолетовый `(70,35,95)`.
- `vp`, `vs`: отдельные контрольные изображения полей с общей последовательной палитрой из трёх опорных цветов `(25,30,85)`, `(25,130,140)`, `(250,230,60)`.

PNG — только визуализация с 8-битными каналами; расчёты должны читать NPZ. Пользователь выбрал для текущей генерации вариант A (`rg`). Отдельных исходных иллюстраций Василия в папке не обнаружено, поэтому пробы воспроизводят геометрию его массивов, а не неизвестную исходную палитру.

## Превью по группам

Команда `prepare_data.py group-previews` создаёт по одному RGB PNG 350 × 350 для каждой модели: `previews/A/EFVB/00000.png`–`29999.png` и `previews/A/ECVB/00000.png`–`29999.png`. Нормировка берётся из общего бинарного manifest и одинакова для обеих групп. R кодирует VP, G — VS, B равен нулю. Перед чтением каждого NPZ сверяется SHA256; каждый PNG повторно открывается и попиксельно сравнивается с исходным массивом цветов, увеличенным повторением каждой ячейки 5 × 5 раз.

`previews/A/EFVB_overview.png` и `ECVB_overview.png` содержат по 16 моделей с равномерно выбранными ID от 00000 до 29999. Это обзорные выборки, а не изображение всех моделей группы. `previews/A/manifest.json` фиксирует шкалы, число файлов, способ окраса, ID обзорных выборок и контрольную сумму бинарного manifest; он записывается после успешного завершения обеих групп.

Запись и проверка PNG выполняются в восемь потоков. Повторный запуск проверяет уже существующие изображения и создаёт недостающие; несовпадение существующего PNG с ожидаемыми пикселями останавливает команду, а не молча заменяет изображение.

Генерация обеих групп завершена 2026-11-04: по 30000 PNG, всего 60000. SHA256 входных NPZ и попиксельная проверка каждого изображения прошли; оба обзорных листа просмотрены. Mypy изменённого скрипта завершился с кодом 0. Проверки авторские.

Обработаны все 60000 моделей, записаны и точно проверены 60 NPZ общей длиной 42447629 байт (40,48 МиБ). Глобальная шкала VP: 1500–4500 м/с; VS: 615,71051–2999,36597 м/с. Проверки пар, размеров, конечности и допустимости материалов прошли для всего набора. Дополнительно 12 полей из распакованных копий (три модели каждого класса, обе компоненты) точно совпали с NPZ. Проверены размеры всех 30 пробных PNG; обзорная таблица просмотрена визуально. Mypy `research/seismic_dataset/prepare_data.py` завершился с кодом 0. Эти проверки выполнены автором подготовки.

## Проба векторизации, 2026-11-04

`vectorization_probe.py` строит сравнение точных и сглаженных границ для EFVB 15000 и ECVB 00000, 15000, 29999. Источник — пары float64 VP/VS в NPZ, а не квантованные PNG. Материал определяется точной парой скоростей; связная область — отдельная сущность, поскольку один материал может встречаться в нескольких несмежных областях.

Из рёбер ячеек с разными материалами извлекается единый граф интерфейсов, включая внешнюю границу с меткой -1. Общий интерфейс хранится однократно. Цепочки разделяются в узлах ветвления, смены пары материалов и углах внешней границы. Прямые цепочки остаются отрезками; для остальных пробуется кубический B-сплайн по методу наименьших квадратов с закреплёнными концами. При превышении пробного допуска возвращается точная ломаная. Допуск 10 м проверяется на выборке параметров относительно исходной ломаной; это экспериментальный параметр, а не доказанная непрерывная оценка ошибки или утверждённый контракт геометрии.

В `vectorization_trial/` записываются 12 JSON с материалами, исходными цепочками, степенями, узлами и контрольными точками сплайнов; 12 PNG с белыми границами поверх цветной карты ячеек; `comparison.png` и `summary.json`. В колонках сравнения: точные интерфейсы; сплайны исходной карты; сплайны после одного синхронного прохода строгого большинства в окне 3×3. Для третьей колонки меняется метка только при пяти и более голосах одного материала. Граница окна продолжается ближайшей ячейкой. Исходные NPZ и PNG варианта A не изменяются.

| Модель | Области до фильтра | Области после фильтра | Изменённые метки из 4900 |
| --- | --- | --- | --- |
| EFVB 15000 | 8 | 8 | 0 |
| ECVB 00000 | 26 | 25 | 10 |
| ECVB 15000 | 36 | 34 | 21 |
| ECVB 29999 | 20 | 20 | 14 |

Числа областей относятся к 4-связной растровой карте до подгонки сплайнов. Сохранение графовых концов не доказывает сохранения геометрической топологии: пересечения сплайнов, петли, зазоры, площади областей и обратная растеризация пока не проверены. Замкнутые цепочки имеют совпадающие концы, но гладкость касательной в шве не обеспечивается. JSON имеют статус `preview_only_not_validated_for_meshing`; это исследовательская проба, не готовый вход сеткопостроителя. Фильтр большинства не принят как способ изменения исходной среды. Mypy скрипта и короткий CPU-запуск прошли, сравнение просмотрено визуально.

Целевой конвейер: карта материалов → общий граф границ → согласованные сплайны и замкнутые области → линейная четырёхугольная/смешанная сетка → криволинейные элементы с узлами выбранного PET. Геометрический допуск следует отделять от характерного размера элемента и порядка аппроксимации. Для EFVB и простых полос подходит блочное трансфинитное построение; для общей топологии рассматривается Gmsh с recombination. Наличие треугольников требует явного выбора совместимого solver/PET; стандартные high-order узлы внешнего генератора не отождествляются с GLL-узлами SEMGPU. Gmsh не установлен в текущей `.venv`; установка и интеграция ещё не выполнялись.

Источники алгоритмов: [Gmsh, трансфинитные сетки](https://gmsh.info/doc/texinfo/gmsh.html#t6), [Gmsh, неструктурированные четырёхугольники и ограничения recombination](https://gmsh.info/doc/texinfo/gmsh.html#t11), [scikit-image, неоднозначность диагональной связности в marching squares](https://scikit-image.org/docs/stable/api/skimage.measure.html#skimage.measure.find_contours). Реализованная проба использует точные рёбра ячеек, а не marching squares над числовыми ID материалов.

## Пилот ECVB: криволинейная Q2-геометрия

По всему ECVB выбран ID 12404 с четырьмя широкими связными слоями, без мелких включений; минимальная исходная толщина 80 м. `select_layered_model.py` сохраняет данные и критерии в `pilot_geometry/selection.json` и `selected_model.npz`. `pilot_mesh.py` строит исходную квадратную сетку и согласованную со сглаженными границами блочную сетку; обе содержат 4900 элементов с характерным размером 10 м. Полная Q2-карта учитывает центральные узлы и сохраняется при повышении порядка решения. Аналитический минимум якобиана положителен, вертикальные размеры криволинейных элементов 7,019–13,529 м.

`pilot_geometry_plot.py` создаёт `pilot_geometry/geometry_comparison.png` и проверяет соответствие координат p3/p4 фиксированной Q2-карте; максимальная разность 3,411e-13 м. Окрас материалов использует общий вариант A. `pilot_stability.py` оценивает стартовый шаг с учётом масс, жёсткости и ABC; общий выбор для p2–p4 — 18 внутренних шагов на 1 мс записи.

`pilot_run.py` задаёт центральную вертикальную силу Рикера 15 Гц с гауссовым пятном шириной 10 м, свободную верхнюю поверхность, ABC по бокам и снизу, 71 поверхностный приёмник Ux/Uy и снимки на общей сетке. Нагрузка интегрируется по функциям формы и имеет одну физическую нормировку при всех порядках. Без `--run` сценарий проверяет постановку без native-библиотеки. Динамика использует `lin_elast_2d_tenzor_newmark_kim_ceed` с `/cpu/self/gen`; пользователь назначил подготовку нативного Windows-порта. Подготовка сетки и dry-run сами по себе не являются результатом сравнения волн. Полная постановка, критерии сходимости и команды находятся в [протоколе](pilot_geometry/PROTOCOL.md).

Нативный Windows CPU-gen собран и работает; малый криволинейный gen/ref probe сохранён в `windows_tensor_probe_evidence.json`. `pilot_windows.py` задаёт явный CEED prefix и JIT compiler, удерживая DLL-directory cookie весь запуск. `pilot_verify_order.py` проверяет Q2-геометрию и аналитические моменты нагрузки при выбранном порядке. `pilot_compare.py` сопоставляет завершённые массивы с проверкой физической постановки и provenance, считает полные и временные нормы и строит PNG общей шкалы с отдельной шкалой разности. Состояние расчётной серии, результаты и ограничения находятся в [отчёте пилота](PILOT_REPORT.md).

Все десять прогонов p2–p5 завершены. Переход p4→p5 меняет полную запись примерно на 0,15%/0,11% (Ux/Uy), контроль времени на p4 — на 0,0034%/0,0029%. Сглаживание даёт наблюдаемую общую разность 0,84%/0,51%, а в слабой коде 1–2 с — 18,48%/16,08%. Для поздней коды эффект превосходит сумму пространственных поправок в 65–110 раз; для малого общего различия пятикратный запас не достигнут. Итоговые NPZ и PNG лежат в `pilot_runs/`, метрики — в `pilot_runs/comparison/metrics.json`.

## Повтор на сложной модели ECVB 00065

Изолированный опыт находится в `model65/`: пять материалов, восемь связанных областей, стыки трёх и четырёх областей и контакт длиной 10 м. `model65_geometry.py` строит общий граф сплайнов без изменения топологии; `model65_mesh.py` создаёт структурированный контроль и полностью четырёхугольную неструктурированную сетку с полной Q2-геометрией. Для решения p4 получены 4900/6075 элементов и 78961/97669 глобальных узлов соответственно. Положительность якобиана проверена на всей площади каждого элемента, а отдельный аудит подтвердил сохранение связности и контактов.

Физика и источник повторяют первый опыт; общий временной шаг — 72 внутренних шага на 1 мс записи. `model65_run.py` проверяет Q2→p4 embedding и моменты гауссовой силы; `model65_compare.py` сопоставляет завершённые массивы и строит общие шкалы. Постановка и воспроизведение — в [протоколе №65](model65/PROTOCOL.md), сетки — в [PNG](model65/geometry/geometry_comparison.png). Первая пара p4 сама по себе не доказывает сеточной сходимости для этой модели.

Оба двухсекундных расчёта завершены. Полная поверхностная запись отличается на 2,23%/1,37% (Ux/Uy), позднее окно 1–2 с — на 13,75%/6,23%, поле на t=2 с — на 26,07%/22,02%. При этом материал изменился приблизительно на 1,04% площади, а топология сохранена. Эти числа включают изменение геометрии и пространственной дискретизации; отдельной серии сходимости №65 пока нет. Числа, PNG, проверки и ограничения собраны в [итоговом отчёте №65](model65/REPORT.md).

from pathlib import Path
import numpy as np

path = Path("research/seismic_dataset/binary/EFVB_00000_00999.npz")
with np.load(path, allow_pickle=False) as block:
